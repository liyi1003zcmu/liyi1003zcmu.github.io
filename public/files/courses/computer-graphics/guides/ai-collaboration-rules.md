# 《计算机图形学》课程设计：AI 提示词与人机协作过程记录规范

> **2026 年秋季学期｜主题“纪念”｜学生执行版**  
> 配套：[课程设计指南](./course-design-guide.html)｜[个人记录模板](./ai-prompt-template.html)。

## 一、提交目的和基本原则

课程设计成绩不仅看最后作品，还要结合个人实际贡献，观察从**发现问题 → 明确目标 → 人机分工 → AI 反馈 → 自主判断 → 核验修正 → 结果与反思**的过程。

1. **逐人逐阶段、保留全部原始输入。**每组 3～4 人；每人每阶段一个独立记录文件。记录本人实际发出的、与本项目有关且能够查看的**所有**提示词/指令，按发生顺序保留，包含失败、追问、未采用方案、AI 编程工具和 Vibe Coding 的可见输入；不能只交“最佳提示词”。
2. **原文和事后说明分开。**原始输入逐字保留；目标、理由、验证、反思写在专门字段中。不得将事后整理或 AI 帮忙润色后的内容冒充历史提示词。
3. **过程与证据对应。**只有原始提示词不足以说明能力，需通过 AI 实际反馈、人工决策、代码变化、测试记录、运行结果、报告和答辩交叉核验。
4. **降低记录负担。**每条可见输入只做一次“逐条记录”；一项关键任务完成后，额外做一次“任务闭环记录”。不要求把同样的长篇总结抄到每条提示词下面。
5. **不按使用量判分。**提示词数量、字数、使用某个 AI 产品或采用 Vibe Coding，本身不等于素养或个人贡献；没有使用 AI 的成员须如实声明，并用等效的设计、代码和测试过程证据接受课程评价，**不能据此推断其人机协同表现**。
6. **仅收项目范围数据。**与项目无关的私人对话不用提交；共享会话由实际发出指令的成员登记，其他参与者通过记录 ID 说明各自贡献，不能一条对话复制成多人“个人提示词”。

## 二、统一格式、目录与三个提交节点

提示词记录首选 **UTF-8 编码 `.md`**；允许 **`.docx`**，正文必须是可选中、可复制、可自动提取的文字，按模板使用普通段落和原样分隔符；不接受截图、PDF、聊天链接或嵌图 Word 作为唯一记录。纯文本指**原始提示词是可提取文字**，并不声称 Word 格式本身是纯文本。工具导出（TXT/HTML/JSON/会话日志）可另附供核对，不替代标准记录。

统一阶段：`S1` 第七周（选题初步设计）、`S2` 第十三周（详细设计及阶段实现）、`S3` 最后一周（结题与展示）。**具体截止时刻以课程平台为准**。三次均提交到课程平台相应作业/目录。

```text
课程设计_S1_第X组.zip
├── 初步设计报告.pdf
├── 开发环境与AI工具清单.md
└── AI记录/
    ├── 提示词_学号A_S1.md
    ├── 提示词_学号B_S1.md
    ├── 提示词_学号C_S1.md
    └── 提示词_学号D_S1.md           # 四人组填写
```

`S2` 包含 `详细设计报告.pdf`、`阶段源代码_第X组.zip`、更新的 `开发环境与AI工具清单.md`、每人的 `提示词_学号_S2.md`。`S3` 包含最终报告、完整源代码、展示 PDF/必要视频、最终工具清单及如下材料：

```text
AI记录/
├── 全组提示词索引.md
├── 提示词_学号A_S1.md
├── 提示词_学号A_S2.md
├── 提示词_学号A_S3.md
├── 提示词_学号B_S1.md
├── 提示词_学号B_S2.md
├── 提示词_学号B_S3.md
├── ...                           # 其他成员各三个阶段
└── 补充记录说明.md                # 仅有补录或缺失时需要
```

- **一个阶段只记录该阶段新增的原始输入**；跨阶段任务用历史记录 ID 引用，避免重复计数。最后归集 S1～S3 原阶段文件，不能只交后来重写的“精选合集”。
- `全组提示词索引.md` 至少一人一行：组号、项目、姓名、学号、承担模块、S1/S2/S3 文件名及记录数、使用工具、关键功能/成果路径、异常与缺失说明；所有条数仅用于查漏。
- 发现漏记时保留原历史文件并附 `补充记录说明.md`：实际发生阶段、补录时间、遗漏原因、来源证据及补充记录 ID；不得编造事件发生时间或暗中改写旧记录。

## 三、开发环境、AI 工具与来源说明（组级必交）

`开发环境与AI工具清单.md` 从 S1 建立，S2/S3 更新，至少包含：项目/组号；操作系统、IDE/编辑器及关键版本；编程语言、图形引擎/框架与版本；构建/启动方法和关键依赖；每人使用的 AI 对话工具、可见模型信息、IDE Agent / Vibe Coding 工具、具体用途及使用方式；项目级 Agent 规则文件/自定义指令的路径与版本；第三方代码/模型/图片/音乐的来源和许可核对情况。未使用写“未使用”，界面未提供模型版本写“未显示”，不可猜测。

**工具选择补充一句真实理由即可：**为什么这种工具适合当前任务？有哪些已知限制或需要人工把关之处？这提供了与 6.3（选择策略）和 7.3（能力边界）相关的证据，不要求虚构工具比较过程。

## 四、个人逐条记录：每个真实输入一个记录块

文件表头统一包含：`项目名称`、`组号`、`阶段`、`学号`、`姓名`、`本人负责模块`、`本阶段AI工具`、`本阶段提示词条数`、`记录说明`。按真实时间顺序填写；不能获得的时间写“未记录”。推荐用以下**固定字段、固定顺序、固定分隔符**：

```text
[RECORD_BEGIN]
记录ID：G03_S2_实际学号_001
时间：实际时间 / 未记录
工具与模型：工具名；模型名或未显示
会话标识：无敏感令牌的会话编号
关联任务ID：G03_实际学号_T001
关联阶段与任务：S2；光源与阴影模块
提示词类型：目标 / 背景 / 追问 / 整合 / 比较 / 核验 / 理由 / 分工 / 局限 / 调试 / 其他（可多选）
输入形式：手动 / 粘贴 / 语音转写 / 工具内指令 / 其他
关联上下文：关联文件路径、报错、图片或附件名称；没有写无
[PROMPT_BEGIN]
此处原样粘贴本人实际发送的完整提示词（仅原文）。
[PROMPT_END]
AI反馈：当次真实反馈的简要摘要；影响关键决定的完整输出另附路径
学生处理：采纳 / 部分采纳 / 否决 / 待验证 / 未使用输出
处理理由：具体理由；尚无决定写待定
人工操作：本人做了什么修改/检查；没有写无
核验状态：通过 / 未通过 / 部分通过 / 未验证 / 不适用
核验方法与结果：方法、观察结果、测试文件或任务闭环ID；没有写未验证
风险与局限：发现的风险或限制；未评估写未评估
成果证据：源文件/版本/测试/报告的相对路径；没有写无
后续记录ID：后续追问/修正的ID；没有写无
[RECORD_END]
```

**填写要点：**

- `记录ID` 全组唯一，使用 `G组号_S阶段_学号_001` 形式；`任务ID` 使用 `G组号_学号_T001`，不同成员独立编号，同一任务跨阶段保持同一任务ID；同一会话每次新输入都分开记录；不要把全部会话压缩为“一条大提示词”。
- `[PROMPT_BEGIN]` 至 `[PROMPT_END]` 内只保存**真实原文**，含约束、源代码、报错、原语言；评价语和反思写在外部字段。原始内容涉及密钥/隐私时仅替换敏感值并说明脱敏范围；不得重写非敏感部分。
- `提示词类型` 是学生的辅助索引，不是素养评分；不会比较或核验时不可为了满足标签而虚构。教师后续以原文和证据重新编码。
- **每条至少说明 AI 实际反馈和本人处理。**若该次只是问概念、尚无成果，核验/文件可如实写“未验证/无”；关键设计、生成代码、纠错、功能验收等需具体填写理由、方法和证据，详见下一节闭环记录。
- AI 答复可在逐条记录中准确概述，但**关键代码、关键方案、错误输出及影响最后决策的原始答复**应另附可读原文或工具导出，标明关联记录 ID；不可把本人概述伪装为 AI 原话。
- 图、附件、工程上下文只记录可核实的名称/相对路径；应保留允许共享的必要原始材料。IDE 自动读取了哪些文件，如界面/日志不可知，填“工具未提供”，不能猜测。
- 多人共享会话记录实际发送人；其他成员在本人阶段说明或闭环中引用相关记录 ID，说明自己参与的评审、实现、验证工作。

### Vibe Coding 与 Agent 额外要求

记录本人能看到且实际发出的**每一条**目标描述、修正要求、报错反馈、撤回/重试和验收指令；注明工具执行后可见的文件变动、自己进行的人工检查和运行验证，能导出的操作日志作为补充附件。项目级规则文件另行保存版本与路径。**隐藏提示词、模型内部推理、看不到的后台调用一律不编造。**被动代码补全没有可见个人提示词时在工具清单中说明，不虚构记录；工具历史缺失需注明原因与能够核实的其他证据。

## 五、关键任务闭环记录：把“提示词”变成“素养证据”

**每人每阶段，对本人实际负责且已开展的关键任务填写闭环记录；原则上每个关键功能或重要技术决策至少一份。**可合并一串相关提示词，不必每次追问写一份。S1 适合选题、需求和路线，S2 适合场景/相机/光照/纹理等设计实现，S3 适合测试、修正、优化和交付。没有已开展的关键任务时如实注明并提供当前进度，不必为了数量编造案例。

```text
[TASK_BEGIN]
任务ID：G03_实际学号_T001
任务名称：〔真实任务〕
负责人与参与人：〔学号；分别说明工作〕
关联提示词ID：〔列出此任务相关全部记录ID或连续编号范围〕
任务目标与验收条件：〔要解决什么问题，怎样算完成〕
开始前已有方案/判断：〔本人当时真实想法；没有记录写未记录〕
人机分工及边界：〔人负责目标、决定、理解、验收；AI实际协助什么；为何如此分工〕
方案与选择理由：〔真实考虑的候选方案、比较依据；没有比较写未比较〕
AI实际作用与人工改动：〔AI建议/生成的内容、本人修改/否决的内容和原因〕
验证方法与实际结果：〔测试输入、预期、观察、通过/失败、证据路径；未做写未验证〕
问题、限制与风险处理：〔模型出错/依赖/性能/授权/隐私等；无发现或未评估如实写〕
最终决定与成果：〔采用/否决/待完成，关联源码/提交/报告/版本〕
本人反思及下一步：〔学到什么、有什么证据、尚不能证明什么；下一步做什么〕
[TASK_END]
```

**建议提供的具体证据：**图形学概念与方法（投影、坐标系、Phong、纹理等）是否理解；设计是否将场景对象、属性、关系整理成可实现结构；方案选择是否基于功能、兼容性与性能；AI 代码是否由本人阅读、修改和运行；是否有错误截图、测试用例、运行输出、相关提交版本。**写“已测试”不等于验证证据，须说明怎么测、看到什么。**没有对比、失败或创新时允许如实写“无/未发生”。

## 六、每人每阶段的简短反思（在文件末尾）

建议 150～300 字，围绕下面五问填写，并尽量引用记录 ID / 任务 ID / 源文件；不要求每个维度都有正面案例：

1. **主动性与持续改进：**本阶段由我主动提出或在困难后改进的真实行动是什么？证据在哪里？
2. **工具选择与使用：**我为什么使用/不使用某工具？提示词、运行环境、学习资源怎样帮助任务？
3. **人机分工与判断：**我让 AI 辅助什么、由自己负责什么？哪次 AI 建议未被直接采用，为什么？
4. **核验与反思：**我依据什么检查 AI 输出？发现了什么错误或限制？没来得及验证的事项是什么？
5. **应用与责任：**有哪些与源码/效果可对应的成果？是否说明 AI/素材来源、脱敏及安全/真实性问题？

## 七、阶段重点、诚信和特殊情形

| 阶段            | 应保留的提示词与闭环重点                                                     | 其他证据                             |
| --------------- | ---------------------------------------------------------------------------- | ------------------------------------ |
| **S1 第七周**   | “纪念”主题理解、目标界定、场景对象与属性、备选路线、工具选择、初始分工与边界 | 初步报告、分工、可行性说明           |
| **S2 第十三周** | 模块设计、代码生成及人工阅读、坐标/光照/纹理等错误分析、方案比较、阶段测试   | 阶段源码、模块图、测试记录、提交版本 |
| **S3 最后一周** | 整合、性能与视觉效果优化、缺陷核验、版权与内容准确性检查、成果展示及反思     | 完整代码、运行演示、最终报告、答辩   |

- **真实性：**不得伪造、删除失败过程、为得分补写“理想提示词”，或把 AI 输出写成独立个人成果。历史遗漏按第三节补录。
- **隐私与安全：**不得上传密码、API Key、访问令牌、未经授权的个人资料或内部素材；对已有对话脱敏，以 `[已脱敏：类型]` 占位并在表头注明。不得借脱敏删除与学习分析有关的整段内容。
- **版权与主题表达：**注明第三方代码、模型、图像、音乐来源、授权或使用条件。涉及真实纪念人物、事件时，对可核实的事实做来源核验；尊重隐私、肖像及表达情境。普通纪念项目的这些要求属于本课程实践，不等同于标准中的临床患者责任指标。
- **未使用 AI：**仍提交阶段文件，填写 `本阶段未使用AI：是`、本人实际工作、相关设计/代码/测试证据和阶段反思。提示词条数为 0，不填写虚假的逐条/闭环对话。教师以对应课程目标的非 AI 证据评价，**不据此给“人机协同素养”判零或判优**。
- **资料用于分析：**课程评分按公布规则开展。若后续用于教学研究、论文或公开案例，须另行按学校适用要求落实告知、必要的同意或伦理审查和脱敏；不默认课程提交即同意对外公开聊天内容。课程平台仅在授权范围使用记录。

## 九、提交前自查

- [ ] 本人有本阶段独立 MD/DOCX 文件；结题时全组三阶段文件及索引齐全。
- [ ] 原始提示词全部为可提取文字，逐条编号，失败、追问、未采纳均保留；没有将事后说明写进原文。
- [ ] 工具/模型可见信息、IDE、运行环境、任务 ID、会话/来源和版本路径可核查。
- [ ] 逐条记录写明实际反馈、处理与理由，关键任务有闭环，实际测试写明方法与结果。
- [ ] 原始 AI 关键输出、源码、日志、报告与记录 ID 能互相定位；自述和证据区分清楚。
- [ ] 工具/素材使用情况已披露，密钥隐私已脱敏；不适用或无证据处没有强行填写。
- [ ] 已按 S1/S2/S3 上传课程平台对应作业，并下载检查可打开/解压。
