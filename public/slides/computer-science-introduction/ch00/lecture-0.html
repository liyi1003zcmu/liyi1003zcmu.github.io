PART 01

从 C 语言开始，建立程序设计的基本能力

🎯 学完 C 语言，希望具备什么能力？

  • 表达问题：用数据、条件、循环表达解决思路；
  • 组织程序：逐步掌握函数、数组、指针、结构体及文件操作；
  • 检验结果：能够独立编写、调试和测试一个有实际用途的小程序。

🧠 为什么从 C 语言入手？

  • 观察程序如何运行：理解变量、数据表示和内存的基本关系；
  • 建立逻辑习惯：练习分解问题、处理边界、跟踪程序状态；
  • 为后续学习打底：学习新语言时，可以迁移算法、调试和问题分析方法。

编程能力是怎样慢慢练出来的？

只看例题，容易出现的情况

看讲解时感觉理解了，换一组输入或稍改题目，就不知道下一步怎么写。

关键差别：理解一个例子，不等于能够独立解决新问题。

写一写、测一测、改一改

通过变量状态追踪、循环边界判断、错误定位反复练习，逐步建立对程序行为的直觉。

建议：把练习分散到每周，短时间但持续动手，并复盘错误。

💡 一个类比：学编程有点像学乐器：看懂示范很有帮助，但手上真正练过、遇到错误后调整，才会逐渐熟练。

学习不必一直处于“单机模式”

🤔 可能遇到的情形

  • 不确定何时提问：觉得问题太简单，担心打扰老师或同学；
  • 难以描述问题：知道程序不对，却说不清预期、实际结果与尝试；
  • 合作经验较少：小组任务中还在学习分工与交流。

🌱 可以逐步养成的习惯

  • 问得具体：说明目标、现象、错误信息和已尝试的方法；
  • 合作互助：可以结对分析程序，也尊重各自独立完成的部分；
  • 保持联系：通过课后答疑、课程群和项目交流慢慢建立学习网络。
课堂小建议：不必一开始就擅长社交；一次具体的提问、一次认真倾听，都是有效沟通的起点。

互动 2：用纸和笔跟踪一个循环

不用复杂算法。先独立写下答案，再和旁边同学对照。

题目 1：循环边界

int sum = 0;
for (int i = 1; i <= 5; i += 2) {
    sum += i;
}
printf("%d\n", sum);

A: 9　B: 15　C: 6

题目 2：先判断再执行

int n = 7, count = 0;
while (n > 0) {
    n -= 3;
    count++;
}
printf("%d\n", count);

A: 2　B: 3　C: 4

点击查看变量变化

同样的结果，为什么有的程序少做很多步？

代码 A：找到答案后仍继续检查

// 判断正整数 n 是否是素数
int is_prime = 1;
for (int i = 2; i < n; i++) {
    if (n % i == 0) {
        is_prime = 0;
    }
}

若输入 n = 100，检查到 i = 2 时已知道它不是素数，但循环仍继续。

代码 B：发现因子后结束检查

int is_prime = 1;
for (int i = 2; i <= n / i; i++) {
    if (n % i == 0) {
        is_prime = 0;
        break;
    }
}

✔ 输入 n = 100 时，B 只需尝试 i = 2，A 则会继续遍历其余候选值。

💡 思考：这里同时做了两种优化：找到因子就 break；只检查到平方根附近。请比较它们各自减少了什么工作量。（此示例假设 n ≥ 2）

PART 03

AI 可以帮忙，但判断和学习仍属于自己

🔎 使用 AI 时容易忽略什么？

  • 跳过理解：直接复制答案，遇到题目变化便无法调整；
  • 忽略错误：生成的解释或代码可能看起来合理，却含有逻辑问题；
  • 缺少记录：忘记自己怎样提问、验证，最后也说不清为什么采用某个方案。

✔ 有效的人机协作是什么样？

  • 请 AI 提供思路：解释概念、列举边界情况、辅助定位问题；
  • 自己做实验：编译运行、对比预期结果，检查关键判断；
  • 能说明取舍：知道采用了什么建议、为什么采用、还有哪些局限。

一套可执行的 AI 协作方法

① 明确任务与规则

先读懂题目，确认课程允许 AI 协助到什么程度；需要独立完成的部分，要按照要求完成。

② 保留自己的初始想法

先写简要思路或程序草稿，再向 AI 询问解释、可替代方案或可能的错误。

③ 验证、修改并留下证据

对 AI 的建议进行编译、运行和边界测试，记录“采纳了什么、为什么、结果如何”。

判断标准：提交的程序应符合课程规定，关键逻辑能解释、结果经过核验，AI 的参与过程可追溯。

互动 3：给一段 AI 代码设计测试

题目：“用 switch-case 返回某年某月的天数。” 假设 AI 给出以下程序，是否可以直接使用？ 

int get_days(int year, int month) {
    int days = 0, is_leap = 0;
    if (year % 4 == 0) { // 判断闰年？
        is_leap = 1;
    }
    switch (month) {
        case 1: case 3: case 5:
        case 7: case 8: case 10: case 12:
            days = 31;
        case 4: case 6: case 9: case 11:
            days = 30;
            break;
        case 2:
            if (is_leap = 1) days = 29;
            else days = 28;
            break;
        default: days = -1;
    }
    return days;
}

🕵️ 先提测试数据：用 2024 年 1 月、2023 年 2 月、1900 年 2 月分别检验，能发现什么？

测试数据模拟器

原因 1：31 天的 case 缺少 break，会覆盖成 30。

原因 2：if (is_leap = 1) 是赋值而非比较，平年的 2 月也得到 29。

原因 3：只按“能被 4 整除”判断闰年不完整，世纪年还要检查是否能被 400 整除。

注意：一个测试用例可能同时受到多个 Bug 影响；修复一个问题后要重新测试。

把 AI 当学习伙伴：三个可复用的提问方式

1. 扮演苏格拉底助教

我正在用 C 语言练习 while 循环。
这是我的代码与报错信息。
请先不要给出完整源码，
用问题引导我检查循环变量为什么没有递增。

2. 边界测试助手

我已经写好了这个素数判断循环。
请作为极端刁钻的测试员，
请检查当输入 0、1 或负数时，
我的程序分支是否会发生异常？

3. 逻辑流程推演

我不理解这段嵌套 switch 的跳转逻辑。
请用单步跟踪的方式，
按步骤列出变量的变化并解释跳转顺序。
