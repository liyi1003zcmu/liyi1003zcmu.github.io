Bridge-in · 0–4 min

CPU 和 GPU 为什么要分工？

上一课停在这里

我们已经知道一幅图像来自对象 + 相机 + 光 / 材质。

现在的问题是：这些描述怎样真正变成屏幕像素？

【参考答案】 CPU 负责高层逻辑与场景组织（如对象状态更新、资源管理、绘制指令提交），并通过 Graphics API 传递给 GPU；GPU 拥有海量并行核心，负责将顶点数据经几何变换、图元装配、光栅化和片元着色等管线步骤，高效计算出海量屏幕像素的颜色值并写入帧缓冲。

想一想1 min

从“顶点数组”到“屏幕像素”，你认为至少需要经过哪三步？先写关键词，不求准确。

【互动提问 1/4 参考答案】 1. 顶点处理（Vertex Processing）：顶点着色器将 3D 顶点坐标从模型/对象空间变换至屏幕裁剪空间； 2. 图元装配与光栅化（Primitive Assembly & Rasterization）：将顶点组装为三角形图元，并计算覆盖的屏幕离散采样点，生成候选片元（Fragment）； 3. 片元处理与写入（Fragment Processing & Tests/Blend）：片元着色器计算各点颜色，经深度测试与混合判断后最终写入帧缓冲输出像素。

Why GPU?

为什么图形计算天然适合 GPU？

2.07 M

1920 × 1080 像素 / 帧

124 M

约 1.24 亿像素 / 秒 @ 60 FPS

× many ops

变换、插值、纹理、光照、深度、混合……

大量元素执行相似计算 → 高吞吐并行处理 → GPU

【参考答案】 因为图形渲染涉及海量像素与顶点（如 1080P/60FPS 每秒需处理超 1.2 亿像素），且绝大多数数据处理的计算逻辑完全相同（如矩阵变换、插值、光照计算）。GPU 拥有成千上万个并行核心，专为高吞吐量的 SIMD/SIMT 并行计算设计。

课堂提问

旋转相机后，模型的世界坐标是否改变？如果没有，为什么画面看起来发生了变化？

观察目标2 min

区分 Model 矩阵改变的是对象姿态，View 矩阵改变的是观察方式。

【互动提问 2/4 参考答案】 1. 世界坐标未改变：Model 矩阵未改变，模型在世界空间中的绝对位置和姿态保持不变。 2. 画面变化原因：旋转相机改变了观察变换（View 矩阵），即改变了观察者坐标系。从相机视角来看，物体的相对坐标发生变化，导致投影到屏幕上的像素位置随之改变。
Vertex processing · 15–22 min

顶点处理：同一个点，要经历多个坐标系统

核心任务

  • 对象坐标 → 世界坐标
  • 世界坐标 → 相机坐标
  • 相机坐标 → 投影 / 裁剪空间
  • 传递颜色、法向量、纹理坐标等属性

每个坐标变换都可以表示成矩阵运算。

Demo思考问题

在 Demo 的 Model / View / Projection 阶段中，同一个顶点的数值在哪一步开始因为“相机”而改变？这个改变说明了什么？

【Demo思考题参考答案】 1. 数值在 View（观察变换）阶段开始因相机改变； 2. 说明 Model 变换仅定义物体本身的定位与姿态（与观察者无关），而 View 变换建立以相机为参照系的相对坐标系。

Demo思考问题

调窄裁剪窗口时，跨越边界的三角形是整体消失，还是被截出新的可见部分？这一步的输出仍然是三角形吗？

【互动提问 3/4 参考答案】 1. 只保留可见部分：跨越视锥体边界的图元在裁剪（Clipping）阶段被切割，边界处产生新顶点并重构为新的可见图元。 2. 提前裁剪的原因：几何阶段裁剪能及时剔除完全在视野外的图元，避免后续光栅化和片元着色器执行无意义的海量计算，极大节省 GPU 算力。

课堂提问

片元着色器算出的颜色是否一定进入屏幕？如果两个模型投影到同一个位置，最终由什么决定谁可见？

观察目标2 min

建立关键区分：Fragment 是候选结果，Pixel 是最终写入帧缓存的结果。

Demo思考问题

切换到深度测试阶段并降低已有深度值：片元着色器已经算出的颜色为什么可能没有写入帧缓冲？

【互动提问 4/4 参考答案】 1. 不一定：片元（Fragment）仅是候选像素，必须通过深度测试、模板测试和混合等处理阶段后才能写入帧缓冲。 2. 可见性决定因素：由深度测试（Z-Buffer）决定。离相机更近（深度值更小）的片元通过测试覆盖已有像素；若深度值大于深度缓冲现有值，则该片元会被直接剔除（Discard），所算颜色不会写入帧缓冲。

片元为什么能得到颜色、深度、纹理坐标？

顶点只给出端点属性

A 红色、B 绿色、C 蓝色；或者三个顶点各自具有纹理坐标、深度等。

光栅化阶段进行插值

三角形内部每个片元获得连续变化的属性值，交给片元着色器继续处理。

【参考答案】 依靠光栅化过程中的线性/透视校正插值算法（如重心坐标插值）。顶点着色器输出各顶点属性，光栅化器计算片元在图元内部的相对位置后，对顶点属性进行内插，计算出内部各片元的专属属性。

From old OpenGL to WebGL
