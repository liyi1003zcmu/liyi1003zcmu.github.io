从物理开关到信息表示：
比特、字节与十六进制
计算机一切信息的最小物理单位只有 0 和 1，按权展开是理解一切进位制的通用钥匙。
比特 Bit 字节 Byte 按权展开 十六进制 0x

先看最小单位：0 和 1（比特与字节）

1 bit（位）= 1 个二进制开关（0 或 1）　　8 bits = 1 Byte（字节，内存最小寻址单位）

单个比特的局限

1 个 bit 只能记录 2 种状态（如高低电平、对与错）。面对现实世界纷繁复杂的数值，必须将多个 bit 捆绑使用。

8位字节的丰富表达

8 个 bit 排成一排，可以构成 \(2^8 = 256\) 种截然不同的 0/1 状态组合。内存中的每一个字节都有唯一的物理内存地址。

在内存中，一切数据（无论是居民的血压数值、还是字符姓名）在物理芯片上都只是一串由高低电平构成的 0 和 1。

动手拨动 8 个二进制位：体验位权展开

💡 操作提示：从右往左位权依次为 2⁰=1, 2¹=2, 2²=4, 2³=8, 2⁴=16, 2⁵=32, 2⁶=64, 2⁷=128。尝试将第 7、5、3、1 位设为 1，观察十六进制与十进制结果。

进位计数制：十进制、二进制、八进制与十六进制

进制类型 基数与数码 C 语言前缀表示 十进制 10 十进制 16 应用场景
十进制 基数 10，逢十进一（0~9） 无前缀（默认），如 16 10 16 人类日常思维与常规输出
二进制 基数 2，逢二进一（0, 1） 0b / 0B（C99扩展） 0b1010 0b10000 硬件底层位串直接对应
八进制 基数 8，逢八进一（0~7） 以数字 0 开头 012 020 传统文件权限、历史系统

为什么程序员钟爱十六进制？ 因为 1 位十六进制数正好对应 4 位二进制（半字节，Nibble），8 位刚好写成 2 位十六进制（如 0xFB），紧凑且绝不丢失位结构。

一个问题：负号存在哪里？

纸面上的数学写法

-5

人类使用专门的符号 - 标识负数，使用数字 5 标识绝对值大小。

机器的物理现实

[ ? ] 0 0 0 0 1 0 1

内存电路上只有 0 和 1，无法存入第三种“减号”形状的符号！

工程妥协：牺牲最高位（最左侧的一位）作为符号位（Sign Bit）：约定 0 代表正数，1 代表负数。

原码与反码：负数的最初尝试与局限

原码（Sign-Magnitude）

最高位作符号位，其余各位为数值的绝对值：

+5 → 00000101　　-5 → 10000101

致命缺陷：零有两种编码：+0 (00000000) 与 -0 (10000000)；且无法直接用普通加法器做减法！

反码（Ones' Complement）

正数反码与原码相同；负数符号位为 1，数值位按位取反：

+5 → 00000101　　-5 → 11111010

局限：依然存在 +0 (00000000) 与 -0 (11111111) 的二义性，跨零计算需要循环进位。

补码的诞生：加1让减法彻底转化为加法

原码表示 -5
10000101
→
数值位取反（反码）
11111010
→
末位加 1（补码）
11111011

硬件革命：减法变成加法

在补码体系下，\(A - B = A + (-B)_{\text{补}}\)。CPU 内部只需要设计结构极为简单高效的加法器，无需专门的减法器硬件！

消除零的二义性

+0 的补码是 00000000；-0 取反加 1 后为 [1]00000000（溢出进位丢弃），同样归一为 00000000！

四种编码横向比较器（交互演练）

观察体会：对于正数，原码、反码、补码三者完全相同；而对于负数，三者呈现出精巧的位演化规律。

四种编码的核心差异对比总结

补码为什么能表示 -128？不对称区间之谜

8位原码/反码的取值范围

-127 ～ +127

由于 +0 与 -0 重复占用了 2 个编码位置，因此 256 个状态只能表示 255 个独立数值。

8位补码的取值范围

-128 ～ +127

因为零只有唯一编码，多出来的一个位串 10000000 在数学上恰好被定义为最小负数 -128！

重要推论：任何 \(n\) 位补码整数表示的范围都是不对称的：\([-2^{n-1}, \; 2^{n-1}-1]\)。负数总是比正数多一个！

补码加法：让机器只做自然溢出的位加法

试一试：5 + (-5) 产生进位溢出，低 8 位自然保留 0；而 127 + 1 会发生什么？符号位从 0 翻转为 1，产生严重的整型溢出（变成 -128）！

有符号与无符号：解释规则变了

同样是内存中的 11111111₂ (0xFF)：
若作为 signed char 解释，它是补码 -1；
若作为 unsigned char 解释，它是纯无符号正数 255。

有符号类型（默认）

  • 最高位解释为符号位（0正1负）
  • 采用补码运算，支持负数表达
  • char: -128 ~ 127

无符号类型（unsigned）

  • 所有位均作为绝对数值位参与位权展开
  • 只能表示非负数，正数范围翻倍
  • unsigned char: 0 ~ 255

浮点数的三部分架构：符号、指数与尾数

任何一个二进制实数都可以规格化为类似科学记数法的形式：
\[V = (-1)^S \times (1.M) \times 2^{E - \text{Bias}}\]

1. 符号位 \(S\)

1 bit：0 代表正数，1 代表负数。决定整体数值的正负方向。

2. 阶码/指数 \(E\)

保存经“移码（Bias）”偏移后的幂次，决定数值的覆盖范围与数量级。

3. 尾数 \(M\)

保存规格化后小数点后的小数位（最高位 1 隐含不存），决定数值的精度与分辨率。

为什么浮点指数需要“移码（Bias）”？

如果指数也用补码

指数既有正（如 \(2^3\)），也有负（如 \(2^{-5}\)）。如果用补码存储，负指数最高位为 1，直接比较大小极其麻烦，硬件需要复杂的符号判断。

移码：加上一个固定偏置值

单精度 float 偏置 Bias = 127。真实指数是 3，存储时加上 127 变成 130 (10000010)；真实指数是 -2，存为 125 (01111101)。

移码的精妙之处：将所有可能的指数全部平移为非负整数！比较两个浮点数大小时，硬件直接像整数一样逐位比对，极大简化电路设计。

数值范围与表示精度：由阶码和尾数独立决定

范围（由阶码决定）

阶码指数决定了该数值在数轴上的宏观跨度数量级（能表示多大如 \(10^{38}\)，或多小如 \(10^{-38}\)）。

精度（由尾数决定）

尾数的有效位数决定了邻近两个可分辨数值之间的微观刻度分辨率。float 超过 7 位十进制数就会发生舍入变形！

常见误区：“float 范围比 int 大，所以精度一定比 int 高”——错误！ float 虽然范围远超 32 位整型，但其有效数字只有 24 位，表示大整数时会丢失个位甚至低多位精度！

为什么 0.1 无法在二进制浮点中精确存储？

十进制视角的 0.1

在十进制中，\(0.1 = \frac{1}{10}\)，因为分母 10 是基数 10 的质因数，所以它是一位有限小数。

二进制视角的 0.1

在二进制中，分母 10 包含质因数 5，无法表示为 \(2^k\) 的有限和：

0.1₁₀ = 0.0001100110011...₂（无限循环）

因为 float 只有 23 位尾数，double 只有 52 位尾数，无限循环小数必须被截断舍入。因此，计算机中存入的并不是严格的 0.1，而是一个极其逼近 0.1 的近似值！

浮点比较容差实验（调整 Epsilon 验证）

引入容差门限：只要二者差值的绝对值小于一个极小的阈值（如 \(10^{-6}\)），我们就认为在工程上它们“相等”。

正确比较两个浮点数：引入精度门限

#include <stdio.h>
#include <math.h>

const double EPS = 1e-6;   /* 定义允许的工程误差容限 0.000001 */

int main(void)
{
    double a = 0.1 + 0.2;
    double target = 0.3;

    if (fabs(a - target) < EPS) {
        printf("工程判定：数值在容差内相等！\n");
    }
    return 0;
}
记住模式：fabs(a - b) < 1e-6 是处理浮点比较的通用解法。

【诊断题三】 float 和 double 在内存结构与有效精度上有何本质差别？

① 解析：最高位为 1 是负数。补码取反加 1 还原绝对值：11111011 符号不变数值取反为 10000100，再加 1 得 10000101（原码 -5）。因此代表整数 -5。

② 解析：因为 0.1 和 0.2 在二进制中均为无限循环小数，截断存储产生微小舍入误差，相加后结果为 0.30000000000000004，与严格的 0.3 不完全相等。工程上必须用 fabs(a - 0.3) < 1e-6。

③ 解析：float 占 32 位（1符号+8阶码+23尾数），有效数字约 6~7 位；double 占 64 位（1符号+11阶码+52尾数），有效数字约 15~17 位，精度和覆盖范围均大幅超越 float。
