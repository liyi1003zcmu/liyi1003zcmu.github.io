认知冲突：两个同名变量是同一个吗？

int count = 100;     /* Global variable: file scope */

void sample(void)
{
    int count = 0;   /* Local variable: block scope */
    printf("%d ", ++count);
}

int main(void)
{
    sample();
    printf("%d\n", count);
    return 0;
}

预测输出：打印 1 100 还是 1 1？

核心规则——同名局部遮蔽（Shadowing）：
局部变量与全局变量同名时，在局部变量有效的作用域内，局部变量优先，全局变量被暂时“遮蔽屏蔽”。
5:00—7:30。让学生指出两个 count 各自存放在不同的内存单元中，互不干扰。

C 程序的内存分工：静态存储区 vs 动态存储区

静态存储区（Static Data）

  • 存放全局变量与 static 变量
  • 程序启动时一次性分配固定的内存地址
  • 默认自动初始化为 0

动态存储区 / 栈区（Stack）

  • 存放普通局部变量与函数形参
  • 每次调用函数时动态分配栈帧
  • 函数返回时其内存被立即回收交还系统

5.3 / 静态局部变量 static
只在函数内部看得见，
却能在调用结束后活下来
static 局部变量：兼具局部安全的作用域与全程持久的静态存储期。
static 局部变量 一次性初始化 状态保留 调用顺序依赖

普通局部变量 vs static 静态局部变量

版本 A：普通局部变量（auto）

void show(void)
{
    int count = 0;
    count++;
    printf("%d ", count);
}

show(); show(); show();
输出结果：1 1 1
每次调用重新分配栈帧并初始化为 0。

版本 B：静态局部变量（static）

void show(void)
{
    static int count = 0;
    count++;
    printf("%d ", count);
}

show(); show(); show();
输出结果：1 2 3
只初始化一次，后续调用保留上一次的值！
11:30—13:30。强调 static 变量的初始化发生在编译载入期，不是每次执行到 static 语句都重置。

贯穿案例应用 1：慢病随访记录自动编号器

int recordId(void)
{
    static int next = 0;   /* In static storage, initialized once */
    next++;
    return next;
}

int main(void)
{
    printf("Record ID: #%d\n", recordId());   /* Output #1 */
    printf("Record ID: #%d\n", recordId());   /* Output #2 */
    printf("Record ID: #%d\n", recordId());   /* Output #3 */
    return 0;
}

优点：信息隐藏

next 只能在 recordId 内部访问，外部任何函数都无法擅自篡改编号。

缺点：缺乏重置机制

如果新慢病居民建档要求重新从 #1 开始编号，函数接口无法从外部复位清零。

贯穿案例应用 2：动态累计平均函数

double runningAverage(double bmi)
{
    static double sum = 0.0;
    static int n = 0;
    if (bmi <= 0) return -1.0;   /* Guard clause: avoid polluting history */
    sum += bmi;
    n++;
    return sum / n;
}

/* Simulate 3 follow-up measurements for one resident */
printf("%.2f\n", runningAverage(24.0));   /* 24.0 / 1 = 24.00 */
printf("%.2f\n", runningAverage(23.6));   /* 47.6 / 2 = 23.80 */
printf("%.2f\n", runningAverage(23.8));   /* 71.4 / 3 = 23.80 */
看似入参只有一个 bmi，实际计算却暗中依赖了过去所有历史随访数据！

暗礁：隐藏状态带来“调用顺序依赖”

同一个输入，函数一定返回相同结果吗？在有 static 的世界里并非如此！

测试场景 调用序列 每次返回的结果 为什么会这样？
场景 1：完整历史 24.0 → 23.6 → 23.8 24.00 → 23.80 → 23.80 累加了 3 个随访测量值
场景 2：新居民直接测 直接调用 23.8 23.80 只累加了 1 个值（\(23.8 / 1 = 23.8\)）
场景 3：未重启重复测试 再次传入 24.0 23.85（因为 \(95.4 / 4 = 23.85\)） 上一位居民的历史残留污染了新居民！
软件工程警示：隐藏状态会导致无法独立进行单元测试，测试结果受前面跑了什么测试用例的严重干扰！

5.3 / 全局变量的权衡
共享虽方便，
副作用与隐蔽修改代价高
任何函数都能读写全局变量，任何函数也都可能在不知不觉中改坏它。
全局变量 副作用 Side Effect 模块紧耦合 只读 const 防御

教材例5-8：现金收支记账程序

double cash = 0.0;   /* Global balance variable */

void income(double amount)
{
    cash += amount;
}

void expend(double amount)
{
    cash -= amount;
}
教材代码细节找错：
教材原例在从键盘读入 double 变量时错写成 scanf("%f", &value)，必须纠正为 %lf！

利弊深度剖析

便利之处：
income 与 expend 都不需要通过指针或复杂结构传参，直接读写公共余额 cash。

致命风险：
如果系统中扩展出 50 个函数，只要任何一个实习生不小心写了 cash = 0;，整个账户余额瞬间蒸发，几乎无法追踪是哪一行代码下的黑手！

全局变量的本质：破坏函数独立性

规范做法：显式参数与返回值传递

balance = income(balance, 100.0);
balance = expend(balance, 30.0);

✓ 输入什么、输出什么一清二楚；函数无副作用，极其易测。

滥用全局：隐式黑盒交互

income(100.0);  /* Modifies global cash silently */
expend(30.0);

✗ 模块间产生看不见的“强耦合纽带”，牵一发而动全身。

工程守则：不要把全局变量当成“省力不用写参数列表”的偷懒工具！若全局配置无需修改，必须加上 const 修饰！

教材例5-7 题面描述与复数加乘

📋 教材例5-7 题目要求

使用全局变量在 main 与自定义函数之间共享数据，计算两个复数的和与积。输入两复数的实部与虚部，输出它们的和与积。

复数加法法则

\((a + bi) + (c + di) = (a + c) + (b + d)i\)

result_real = real1 + real2;
result_imag = imag1 + imag2;

复数乘法法则（需特别小心！）

\((a + bi)(c + di) = (ac - bd) + (ad + bc)i\)

因为 \(i^2 = -1\)，所以实部必须减去两虚部乘积！

例5-7 深度找错：抓出教材原版经典 Bug

🚨 原教材课件的公式错误

/* Buggy formula: mixed real and imaginary parts */
result_real = real2 * imag1 - real1 * imag2;

测试打假：对于 \((1 + 2i) \times (3 + 4i)\)：
正确实部为 \(1 \times 3 - 2 \times 4 = -5\)。
原课件错码算出的实部却是 \(3 \times 2 - 1 \times 4 = 2\)，差了十万八千里！

✓ 修复后的正确公式

/* Correct math formula: (a+bi)(c+di) = (ac-bd) + (ad+bc)i */
result_real = real1 * real2 - imag1 * imag2;
result_imag = real1 * imag2 + imag1 * real2;

教训：全局变量名字长且相似，极易在编码时手滑敲错变量名而浑然不知！

教材例5-9：用 static 变量计算阶乘

📋 教材例5-9 题目要求

输出 1 到 \(n\) 的阶乘表。要求定义和调用函数 fact_s(n) 计算 \(n!\)，其内部利用静态局部变量保留上一次计算的结果。

double fact_s(int n)
{
    static double f = 1.0;
    f = f * n;
    return f;
}
仔细端详这段 5 行代码：它真的能随时求任意正整数 \(n\) 的阶乘吗？

例5-9 致命陷阱：它根本不是真正的阶乘函数！

调用序列 实际返回值序列 真正的阶乘 \(n!\) 诊断结论
按严格顺序调用
fact_s(1) → (2) → (3)		 1.0 → 2.0 → 6.0 1 → 2 → 6 表面巧合匹配（每步恰好乘上了 \(n\)）
新程序直接算 3!
只调用 fact_s(3)		 3.0 6 彻底算错！（\(1.0 \times 3 = 3\)）
同一个程序中算两次 3!
fact_s(3) → fact_s(3)		 3.0 → 9.0 6 → 6 不可复现！（第二次直接乘上去了）
本质揭秘：fact_s(n) 根本不是求 \(n!\)，它仅仅是“把传入的数乘到内部静态累乘器上”。一旦调用次序颠倒，满盘皆输！

课堂后测：两道出口核心诊断题

出口题一：变量属性判定矩阵

声明语句作用域存储期与跨调用保留
int a = 0;（函数内）函数/块内部自动存储期，不保留
static int b = 0;（函数内）函数/块内部静态存储期，跨调用保留
int c = 0;（函数外）整个文件向后可见静态存储期，全程保留

追问：静态局部变量 b 属于全局变量吗？绝不是！它的作用域仅限函数内部！

出口题二：最小测试序列证伪

如何用最简单的两行代码证明 fact_s(n) 不是通用阶乘？

/* Test: call directly with n = 3 */
double ans = fact_s(3);
printf("%f\n", ans);   /* Prints 3.0 instead of 6.0! */
结论：通用函数必须是幂等、无害、调用独立的。
